# PD для Claude Code: технический аудит и исправление ошибок `visual-calculus`

> Репозиторий: https://github.com/SergeyErmakov85/visual-calculus

## 1. Цель

Провести исчерпывающий технический аудит репозитория `SergeyErmakov85/visual-calculus` (учебный сайт по математическому анализу) и исправить найденные ошибки: технические дефекты сборки/типов/линта, рассогласование маршрутов и данных курса, ошибки в учебном контенте (опечатки, неверные формулы, битые ссылки), проблемы доступности и деплоя. Результат — рабочий проект с прозрачным отчётом о правках, без изменения архитектуры и педагогического замысла.

## 2. Контекст проекта (зафиксировано из репозитория)

**Стек:**

- Vite 5 + React 18 + TypeScript (SWC-плагин)
- React Router DOM v6 (`BrowserRouter`)
- shadcn/ui + Radix UI + Tailwind CSS + `tailwindcss-animate`
- KaTeX + `react-katex` (рендер формул — критично для предметной области)
- Recharts (графики), Framer Motion (анимации), `next-themes`
- `react-hook-form` + `zod`, TanStack Query, `sonner`/`toaster`
- Vitest + Testing Library + jsdom — установлены, но есть только `example.test.ts` с `expect(true).toBe(true)`
- ESLint flat config, `lovable-tagger` (только в dev)

**Структура контента:**

- 11 модулей (0–10), 47 уроков (`src/pages/lessons/Module*/...`)
- 8 справочных страниц по типам функций (`src/pages/functions/...`)
- Интерактивный гид с экранами (`src/pages/Module.tsx` + `src/components/screens/Screen01–04.tsx`)
- 2 страницы визуализаций (`ConfidenceIntervalPage`, `IntegralPage`)
- Контент на русском языке
- Два параллельных источника данных курса: `src/data/courseStructure.ts` (используется для меток уроков) и `src/data/courseData.ts` (используется в `Module.tsx`/screens)
- 60+ маршрутов прописаны в `App.tsx` вручную как импорты + `<Route>` (есть риск дрейфа с данными)

**Деплой/окружение:**

- README указывает на Lovable (с placeholder'ом `REPLACE_WITH_PROJECT_ID`)
- В репозитории одновременно `bun.lock`, `bun.lockb` и `package-lock.json` — три источника зависимостей
- Нет `vercel.json` / `public/_redirects` / `public/200.html` — при `BrowserRouter` это риск 404 на прямых ссылках на статическом хостинге

## 3. Принципы работы

1. Не менять архитектуру, стек и педагогический замысел. Учебный контент трогать только в части ошибок (опечатки, неверные формулы, битые ссылки, неверные подписи к графикам).
2. Атомарные коммиты по Conventional Commits (`fix:`, `chore:`, `docs:`, `refactor:`, `test:`).
3. Сначала собрать полный реестр находок, согласовать приоритеты — потом править.
4. При неоднозначности — остановиться и спросить, не угадывать.
5. Не делать массовые мажорные апдейты зависимостей. Любое повышение мажора — отдельным PR с обоснованием.
6. Не трогать `lovable-tagger`, общую логику синхронизации с Lovable и не переписывать README раздел про Lovable без согласования.

## 4. Этапы аудита

### Этап 1. Здоровье проекта и единый менеджер пакетов

- Зафиксировать единый менеджер пакетов. В репозитории сейчас есть `bun.lock`, `bun.lockb` **и** `package-lock.json` — это конфликтующие источники. Согласовать с пользователем: оставить npm (как в README) или bun. Лишние лок-файлы удалить.
- Запустить и зафиксировать вывод:
  - установка зависимостей (выбранным менеджером)
  - `npm run build`
  - `npm run lint`
  - `npx tsc --noEmit -p tsconfig.app.json`
  - `npm run test`
  - `npm audit` (или `bun audit`)
- Свести предупреждения и ошибки в таблицу с приоритетами 🔴/🟡/🟢.

### Этап 2. `index.html`, метаданные, SEO-базис

В текущем `index.html` обнаружены placeholder'ы Lovable:

- `<html lang="en">` — должно быть `lang="ru"` (контент русскоязычный).
- `<title>Lovable App</title>`, `description="Lovable Generated Project"`, `author="Lovable"`, `og:title=Lovable App`, `og:image=https://lovable.dev/opengraph-image-p98pqg.png`, `twitter:site=@Lovable` — заменить на содержательные значения для проекта (название курса, описание, корректный OG-образ из `/public`).
- Комментарии `<!-- TODO: ... -->` убрать или заменить осмысленным контентом.
- В `README.md` — два упоминания `REPLACE_WITH_PROJECT_ID`: либо подставить реальный ID проекта Lovable, либо переписать раздел нейтрально.

### Этап 3. Маршруты vs данные курса — единый источник истины

В `App.tsx` 60+ маршрутов перечислены вручную, а пути уроков продублированы в `src/data/courseStructure.ts` (поле `path`). Это два независимых источника, которые могут разойтись.

Что сделать:

- Сверить **попарно**: каждый `lesson.path` из `courseStructure.ts` должен соответствовать ровно одному `<Route path>` в `App.tsx`, и наоборот.
- Составить таблицу `{ path → component → пункт в courseStructure → файл существует? }`. Любое расхождение — баг.
- В каждой странице-уроке `LessonLayout` получает `lessonPath` как строковый литерал-пропс (см. `pages/lessons/Module0/FunctionDefinition.tsx`). Проверить, что эти литералы совпадают с фактическим `path` маршрута и с `courseStructure.ts`. Это частая точка опечаток.
- Оценить (но **не делать без согласования**) рефакторинг: data-driven маршрутизация на основе `courseStructure.ts`, чтобы устранить дрейф. Зафиксировать как предложение в отчёте.

### Этап 4. Дублирование `courseStructure.ts` и `courseData.ts`

В проекте два параллельных файла с данными курса:

- `src/data/courseStructure.ts` — модули и уроки с `path` (используется в `LessonLayout`/breadcrumbs).
- `src/data/courseData.ts` — модули со «screens», используется в `pages/Module.tsx` (роут `/guide/:moduleId`).

В `pages/Module.tsx` мапа `screenComponents` объявлена только для `'0.1' … '0.4'` — для модулей 1–10 гид, скорее всего, не отрисует ни одного экрана. **Проверить:**

- какие модули фактически открываются по `/guide/:moduleId`;
- что отображается, если `module.screens[currentScreenIndex]` существует, а `screenComponents[currentScreen.id]` равен `undefined` (вероятно, пустой экран без сообщения);
- задокументировать и предложить фикс (либо корректная мапа на все экраны, либо явное сообщение «экран в разработке», либо скрытие пунктов).

### Этап 5. KaTeX и рендер формул

Это ключевая зона риска для учебного сайта по математическому анализу.

- `katex/dist/katex.min.css` импортируется в трёх местах: `components/LatexFormula.tsx`, `components/ProbabilityTheory.tsx`, `components/lesson/Math.tsx`. Перенести единый импорт в `src/main.tsx` (или в `index.css`), убрав остальные.
- Пройти по всем урокам и проверить:
  - корректность синтаксиса (нет ли `\\` против `\` из-за экранирования в JSX-строках);
  - корректность математики (особое внимание: формулы пределов, производных, экспонент, тригонометрии, кусочно-заданных функций — это самая ошибкоёмкая часть);
  - что формула отображается, а не выводится как сырая строка `f(x)=x^2`;
  - что подписи на графиках (`title`, `label`, `annotations` в `graphProps`) согласованы с формулой и текстом.
- Зафиксировать список всех формул в виде таблицы «страница → формула → корректно?» — это и есть отчёт по контенту.

### Этап 6. Графика (`InteractiveGraph`, `FunctionGraph`, `RiemannIntegralVisualization`, экраны гида)

- Проверить корректность графиков ключевых функций (полиномы, рациональные с асимптотами, синус/косинус/тангенс, экспонента/логарифм, кусочные, модуль, осциллирующие).
- Особо проверить:
  - поведение вертикальных асимптот (модуль 2.1) — нет ли «провода» через разрыв;
  - наклонные асимптоты (2.3) — корректно ли рисуется наклонная прямая;
  - устранимые разрывы (2.4) — есть ли «выколотая точка»;
  - тангенс (6.3) — асимптоты в `π/2 + πn`;
  - точки склейки (8.2) и угловые точки (9.2) — корректность поведения;
  - визуализация Римана (`RiemannIntegralVisualization.tsx`) — корректность сумм и предельного перехода.
- Все находки фиксировать в реестре, но **править только явные баги**, не переделывая визуальный стиль.

### Этап 7. TypeScript, ESLint, типизация

Текущая конфигурация осознанно мягкая:

- `tsconfig.app.json`: `strict: false`, `noImplicitAny: false`, `noUnusedLocals: false`, `noUnusedParameters: false`.
- `eslint.config.js`: `@typescript-eslint/no-unused-vars: "off"`.

Не включать строгий режим целиком (это уведёт во много правок). Вместо этого:

- Запустить `tsc --noEmit` с текущей конфигурацией — он должен пройти. Любая ошибка — баг.
- Запустить ESLint, починить все ошибки и `react-hooks/exhaustive-deps` warning'и.
- Найти `any` в собственном коде (не в `components/ui/*` от shadcn — их оставить как есть) и пометить «требует решения» — список в отчёт, без массовых правок.

### Этап 8. Dev-режим и скрытые ошибки

- В `vite.config.ts` отключён HMR error overlay (`hmr: { overlay: false }`). На время аудита временно включить, чтобы видеть рантайм-ошибки. По итогу — оставить включённым по умолчанию (предложение в отчёт, решение за пользователем).

### Этап 9. Доступность и адаптивность

- `lang="ru"` в `index.html` (см. этап 2).
- Проверить семантику заголовков (`h1`–`h6` без пропусков) на типовой странице урока через `LessonHeader`/`LessonContent`.

- Поведение на мобильных: `use-mobile.tsx` хук используется — проверить ключевые страницы на ширине 360–414px.

### Этап 10. Деплой и SPA-фолбэк

Проект использует `BrowserRouter`, но в репозитории нет `vercel.json`, `public/_redirects` и не настроен SPA-фолбэк. Это означает 404 при прямом переходе по `/module/3/limit-geometry` на статическом хостинге, не сконфигурированном под SPA.

- Если деплой через Lovable — уточнить, обрабатывается ли это платформой.
- Если планируется Vercel/иной статик-хостинг — добавить минимальный `vercel.json` с SPA-rewrite на `index.html`. Не делать без подтверждения хостинга.
